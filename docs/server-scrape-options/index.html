Can scrapes run on the server?

Host mode + scheduled scrapes, despite Akamai blocks that today force VPN IP switches and a real Chrome browser.

  • Project supercharger-tracker
  • Topic server-side scrape options
  • Pages 5

Summary

Verdict

Yes — scrapes can run on the server with host, if you install a real Chrome and fix egress (residential proxy or home IP). Datacenter IP alone will keep failing the way your VPN switches already show.

Browser

Solvable

Chrome + Xvfb / Docker

IP reputation

Main risk

Cloud IPs scored low

Best pure-server

Proxy

Sticky residential for Chrome

Best reliability

Hybrid

Home worker → import

Today vs target

Current

Local scrape / retry-failed (Chrome + home/VPN IP), then export → POST /admin/import/scrapes. Prod Docker is host-only.

Target

One deployment serves the API and runs scheduled scrapes. Needs realistic Chrome and a way to change egress when Tesla blocks.

Two hard problems

Browser realism
Akamai needs JS cookies + Chrome TLS. In-browser fetch via CDP already solves this — browser must actually run (or be remote).
IP reputation
Datacenter IPs score poorly. Home/VPN residential works. Server scrapes without egress strategy work until they don’t.

What to do

  1. If you only want hands-off soon

    Automate the current flow: home/mini-PC cron → scrape → import. Skip server Chrome. Details in Plan.

  2. If everything must live on the server

    Chrome + sticky residential proxy for Chrome only + scheduler in host or a sibling process. Score it in Compare.

  3. Before writing code

    Answer the open questions on Plan (hosting, frequency, challenge rate, budget).
